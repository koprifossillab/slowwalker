# 산출을 넣고 고치는 화면

2026-10-02 · `feature/occurrence-crud` · summer02kini

## 왜

산출은 지금까지 Django 관리 화면에서만 넣을 수 있었다. 관리 화면은 계정이 있어야 하고, 위경도를 숫자로만 받아
자리가 맞는지 눈으로 볼 수 없다. 사람이 "산출을 입력·조회·수정·삭제할 화면" 을 바랐다.

## 무엇을 정했나

- **화면은 Django 제네릭 뷰 다섯(목록·자세히·넣기·고치기·지우기)과 서버가 그리는 템플릿** — 칸과 검사는 모델의 것을
  `ModelForm` 이 그대로 쓴다. 위경도 범위 검사도 모델 `validators` 한 곳뿐이다
- **로그인은 묻지 않는다(지금은)** — 연구소 안에서 시험하는 동안 누구나 고치게 해 달라고 사람이 정했다. 다만 서버가
  연구소 망(172.16.112.0/21) 전체에 열려 있으니 되돌릴 손잡이를 둔다: `SLOWWALKER_EDIT_REQUIRES_LOGIN=1` 이면 넣기·고치기·
  지우기에 로그인을 묻는다. 보기(목록·자세히·지도)는 언제나 열려 있다
- **분류군을 더하는 작은 화면** — 로그인 없이 산출을 넣게 해도 분류군이 하나도 없으면 첫 산출부터 막힌다(분류군은
  관리 화면에만 있었다). 학명·명명자·계급·상위 분류군만 받고, 산출 입력 화면에서 왔으면 그 분류군을 고른 채 돌아간다.
  고치기·지우기·계층 손질은 관리 화면에 남긴다
- **입력 화면에 작은 지도** — 누르면 위경도가 칸에 들어가고, 칸에 적으면 점이 따라간다. 자세히 화면도 같은 지도로 자리를 보인다.
  배경 정의는 `basemaps.js` 로 빼서 세계지도와 함께 쓴다
- **머리줄을 `base.html` 하나로** — 지도·목록·새 산출을 오가는 길이 모든 화면에 있다. 지도 팝업에서 자세히로 간다
- 목록은 50 개씩, 학명·나라·산지·서식지·출처에서 찾고 분류군으로 거른다

## 버린 것

- **관리 화면을 그대로 쓰기** — 계정이 있어야 하고, 지도로 자리를 고를 수 없다. 분류군·계정을 다루는 곳으로 남긴다
- **브라우저 화면(SPA)과 JSON API** — 기록을 하나씩 넣고 고치는 데에는 서버가 그리는 양식이 짧고 시험하기 쉽다
- **분류군을 고르는 칸에 찾아 고르기(autocomplete)** — 지금은 분류군이 적다. 완보동물 종은 1,500 남짓이라 늘면 다시 본다
- **지운 산출을 되살리기(soft delete)** — 지우기 전에 한 번 묻는 것으로 둔다. 필요해지면 다시 본다

## 걸린 것

- `ol.layer.Tile` 에 `set` 이라는 함수를 붙였더니 지도가 통째로 멈췄다 — OpenLayers 가 속성을 적는 제 `set` 을 덮었다.
  `choose` 로 바꿨다. 시험으로는 안 잡히고 화면을 찍어 보고야 알았다
