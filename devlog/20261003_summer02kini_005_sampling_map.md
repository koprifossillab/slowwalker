# 지도에서 채집과 시료를 따라간다

2026-10-03 · `codex/sampling-map-workspace` · summer02kini

## 왜 채집 지점을 먼저 두었나

완보동물 산출마다 좌표와 날짜를 반복해서 적으면 한 산지의 반복 채집, 한 번의 채집에서 얻은 여러 따개비,
한 시료에서 나온 여러 분류군을 구별하기 어렵다. 산지(Site), 채집(CollectionEvent), 시료(Sample)를
따로 두고 산출이 시료를 가리키게 한다. 좌표가 같아도 산지를 자동으로 합치지 않는다.
산지와 시료 사진도 여러 산출에 복사해서 붙이지 않고 각각 제 주인에 붙인다.

기존 산출에는 새 연결을 강제하지 않는다. 예전 좌표와 사진 경로는 남으며, 아직 시료에 연결하지 않은
산출도 지도에 표시한다. 시료에 연결한 산출의 좌표·날짜·채집자는 산지와 채집에서 읽어, 나중에
산지 좌표를 고쳐도 옛 복사본이 지도에 남지 않도록 한다.

## 왜 2D부터 만들었나

이번에는 자료 입력과 연결을 확인하는 것이 먼저다. 소개 화면을 거치지 않고 지도에 들어가며,
왼쪽 자료 목록과 오른쪽 상세 패널을 함께 쓴다. GSM의 배치를 참고하되 코드를 옮겨 오지는 않는다.
기존 EOX 지형 음영과 Sentinel-2 배경을 유지한다. 음영지도는 높이 모델을 기울여 보는 실제 3D가 아니다.
지구본과 3D 지형은 이 자료 API를 함께 쓰는 다음 보기 방식으로 남긴다.

## 연구 해석에서 남겨 둔 경계

Darwin Core의 Location, Event, MaterialSample, Occurrence 구분과 용어를 참고했다.
연월일을 알 수 없는 문헌 기록은 원문 날짜를 남기고 임의의 날짜를 채우지 않는다. 산출 개체 수의
빈칸은 미기록이며, 0을 불검출이나 부재로 해석하지 않는다.

환경 레이어·환경값 추출·MaxEnt는 아직 구현하지 않는다. 다음 단계에서 환경값의 출처, 판,
단위, 해상도, 수심, 기준 기간을 기록하고 현장 측정값과 재분석 자료를 구분한다. MaxEnt의 결과는
우선 서식 적합도로 해석하고, 조사 편향과 공간 분리 검증을 검토한 뒤 확률 해석을 정한다.
변수 중요도를 인과관계나 장거리 이동 기작의 증명으로 표시하지 않는다.

## 검토와 운영

검토용 예시 자료는 별도 DB와 사진 폴더에 둔다. 운영 DB에 가상 산출을 넣지 않는다.
`SLOWWALKER_PREVIEW_NOTICE`를 지정하면 검토 화면에 예시 자료임을 표시한다.
기존 기록 보존, 연결한 산지 좌표 변경, 사진 소유 관계, 입력 검증, 로그인 조건을 검사한다.
검토 브랜치에서 변경을 제안하며 main 병합은 저장소의 기존 운영 규약을 따른다.

검증에서는 Django 자동 검사 38개, 마이그레이션 누락 검사, 정적 파일 수집, JavaScript 구문 검사를
통과했다. 기존 0002 구조에서 0003으로 옮긴 뒤 산출 번호·좌표·문헌·사진 경로가 남는지 별도로
확인했다. 브라우저에서는 지도 위 점 선택, 학명 검색, 환경 필터, 반복 채집과 세 종류의 사진,
지도 클릭으로 좌표를 채운 뒤 저장하기, 상세 화면의 지도 복귀, 좁은 화면의 탐색 패널을 확인했다.

검토 중에는 산출 고유 문헌이 채집 문헌에 가려지는 문제, 새 부모의 관리자 사진 양식 검사,
다른 사용자가 먼저 지운 사진의 수정 화면 오류를 고쳤다. 기존 단독 기록을 시료에 연결할 때
원래 고도와 0으로 적힌 불확도도 보존한다. 새로 적는 불확도는 1 m 이상이며 미상은 빈칸이다.

현재 투영이 표시하지 못하는 극지 좌표는 점을 다른 위치로 옮기지 않고 목록·상세에 남긴다.
마이그레이션 뒤 새 연결 자료를 넣었다면 역방향 마이그레이션 대신 이전 코드와 함께
**변경 전 DB·사진 백업을 복원**해야 한다. 새 사진의 소유 관계와 좌표 없는 연결 산출을
이전 구조로 억지로 바꾸면 자료가 손실될 수 있기 때문이다.
